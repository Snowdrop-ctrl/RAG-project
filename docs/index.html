01

What RAG is

4 min

A language model only knows what it saw in training. RAG adds one step before the model answers: look up the relevant passages in your own documents and paste them into the prompt. The model stops recalling and starts reading.

Use RAG for

  • Facts that change: policies, specs, tickets, contracts
  • Answers that must cite a source
  • Private data the model was never trained on

RAG will not fix

  • Tone, format or style — that is fine-tuning or prompting
  • Reasoning the model cannot do anyway
  • Questions whose answer is in no document
02

Chunking and embedding

6 min

This runs once per document, at upload. A whole PDF is too big to paste into a prompt and too coarse to search, so it is cut into overlapping windows of 200 words and each window is turned into a list of 384 numbers that encodes its meaning.

What an embedding is

A sentence turned into 384 coordinates. Texts about the same thing land near each other, so “vacation days” finds a passage that only says “paid annual leave”. Keyword search cannot do that.

One rule

Documents and questions must be embedded by the same model. Swap the model and every stored vector is meaningless — you re-ingest everything.

03

Question → response

9 min

Everything above happened before the session. This is what runs in the two seconds after someone presses send: embed the question, match it against the stored vectors, keep the best few, build a prompt, call the model.

04

Our stack, and where each part runs

6 min

Four of the five steps run on the machine. Only the final chat call crosses the network, because embeddings are computed locally by a small ONNX model that needs no key.

05

Does the model now have our documents?

5 min

No — and the precise answer matters. Nothing is trained, and the model remembers nothing between requests. But every RAG answer does send the retrieved passages to the provider, and that is the decision to make consciously.

  • Safe The key lives in backend/.env, gitignored. It is never shipped to the browser — a key in frontend code is readable by every visitor in devtools.
  • Safe Embeddings are computed locally. Document text is not sent anywhere during upload or indexing; only retrieval-time passages travel.
  • Decide Check the provider's retention and training terms before indexing anything confidential, and use a business-tier agreement if one is offered. Assume a request can be logged.
  • Gap The API has no authentication yet. Anyone who can reach port 8000 can upload, list, delete and query every document. Add auth and per-user filtering before this leaves localhost.
  • Gap Uploaded text is untrusted input. A document can contain “ignore previous instructions”. Keep the system rules, never let an answer trigger an action on its own, and treat output as text.
  • Option Fully local is one file away. Point llm.py at a local model and no document text leaves the network at all — embeddings and the index already never do.

If someone asks: “so is our data in the model?”

The model's weights are frozen and identical for every customer; our documents are not in them and cannot be. What we do send, per question, is the question and up to four passages — the same way you would paste an excerpt into a chat window. The risk is transmission and logging, not training.
